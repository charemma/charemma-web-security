AI security

All knowledge articles on risks in LLM applications and AI infrastructure. Each entry explains the topic briefly and links to the in-depth article.

LLM applications

Risks in applications built on language models 10 topics
  • KnowledgeLLM01:2026

    Prompt injection

    Inputs – typed directly or hidden in documents, web pages and emails – make a model ignore its instructions or follow someone else’s.

  • KnowledgeLLM02:2026

    Sensitive information disclosure

    A model reveals confidential data – from its training data, the conversation context or connected systems.

  • KnowledgeLLM03:2026

    Excessive agency

    An agent can do more than its task requires: too many tools, too broad permissions, too little human confirmation.

  • KnowledgeLLM04:2026

    Supply chain

    Risks that enter an application through third-party models, weights, datasets, plugins and libraries, including registries and unsafe file formats.

  • KnowledgeLLM05:2026

    Data and model poisoning

    Manipulated training, fine-tuning or embedding data deliberately change how a model behaves.

  • KnowledgeLLM06:2026

    Unbounded consumption

    Unthrottled requests drive up cost and load, or allow a model to be systematically extracted.

  • KnowledgeLLM07:2026

    Misinformation

    Convincingly worded but wrong output that people or downstream systems rely on.

  • KnowledgeLLM08:2026

    Hidden context exposure

    Hidden instructions and context – such as system prompts – become visible and reveal logic, rules or secrets.

  • KnowledgeLLM09:2026

    Vector and embedding weaknesses

    Weaknesses in RAG systems: missing access separation, manipulated or extracted vector data.

  • KnowledgeLLM10:2026

    Improper output handling

    Model output is processed without validation – as HTML, SQL or a shell command – and reopens classic vulnerabilities.

AI infrastructure

Operations, hosts and access around the model 5 topics
  • KnowledgeINFRA·01

    MLOps pipeline & registry

    Training jobs, CI/CD for models and the registry decide which artifact reaches production, and who can swap it on the way.

  • KnowledgeINFRA·02

    Inference infrastructure

    Model servers, containers, GPUs and tenant separation: services like any other – exposed, often weakly isolated, rarely rate-limited.

  • KnowledgeINFRA·03

    Agents & tool access

    MCP and tool servers as the test object: authentication, network reach, sandboxing of execution and the identities they act with.

  • KnowledgeINFRA·04

    Secrets & keys

    Model provider API keys and credentials easily end up in prompts, logs and pipeline variables.

  • KnowledgeINFRA·05

    Logging & traceability

    Which prompts, tool calls and model responses get logged decides whether an incident can be reconstructed – often it cannot.
